2. 如何判断一个网站是否存在SQL注入漏洞？

1>触发点（哪里可能存在注入）

URL参数：?id=1、?cat=2、?page=3 等

表单输入框：登录、搜索、留言板、注册等任何能输入的地方

HTTP头：Cookie、User-Agent、Referer 等（较少见）

<hr class="content-hr">

2>特征（三种现象）

① 报错特征（最直接）

输入单引号 ' 或 and 1=1 后，页面返回数据库错误信息，包含以下关键字：

SQL syntax

mysql_fetch_array

Unclosed quotation mark

Microsoft OLE DB Provider

② 布尔特征（无报错时）

输入 and 1=1 页面正常，输入 and 1=2 页面空白或显示不同内容，说明你的条件影响了SQL查询结果。

③ 时间特征（无报错无回显时）

输入 sleep(5) 或 and sleep(5)，页面响应延迟了5秒，说明代码被执行。

<hr class="content-hr">

3>一句话总结

有参数 + 输入特殊字符后页面异常（报错/逻辑变化/变慢）→ 可能存在SQL注入。

按严重程度：报错 > 布尔 > 时间（报错注入最严重）。报错型最好利用，时间型最难但最通用（不管有没有报错都能测）

5. 什么是js接口？

JS接口就是前端JavaScript代码向后端请求数据时，暴露出来的URL地址（API端点）。

---

举个例子：你打开一个登录页面，输入账号密码，点击登录。浏览器并不会直接把你的账号密码"扔"给后端，而是通过一段JavaScript代码，向后端的一个特定地址（比如 /api/login）发送请求。这个 /api/login 就是一个JS接口。

---

🔍 为什么测试登录框要看JS接口？

因为JS接口会泄露很多后端信息，这些信息可以帮你找到潜在的漏洞

<hr class="content-hr">

🛠️ 怎么找JS接口？

在浏览器里按 F12 打开开发者工具：

然后

> 查看源代码：按 Ctrl+U（查看网页源代码），搜索 .js 文件，点进去看。

> Network（网络）面板：刷新页面，查看所有加载的JS文件，逐一翻阅。

> Sources（来源）面板：直接浏览所有前端资源文件，查看JS代码。

> 使用工具：可以用Burp Suite或Yakit的爬虫功能，自动提取所有JS接口。

6. 接口 ？

> 什么是接口？

接口（API，Application Programming Interface） 简单说，就是不同软件/系统之间沟通的“桥梁”或“约定”。

它定义了一个系统如何向外部提供服务或数据

> 接口有哪些类型？

主要关注前两类：

--Web接口 (HTTP/HTTPS API)

这是最主流的形式，前端和服务器之间、不同系统之间都通过它通信

--库/框架接口 (API)

这是给你写代码时用的，比如编程语言或框架提供的内置函数。

--操作系统接口 (系统调用)

这是软件和操作系统内核打交道的“底层通道”，普通开发者一般接触不到。

--硬件接口

这是硬件和硬件/软件之间的连接标准和协议。
